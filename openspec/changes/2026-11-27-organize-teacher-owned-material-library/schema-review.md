## Recommended physical shape (logical specification, not executable DDL)

Four new owner-scoped relations:
- material_library_collections: id UUID PK, teacher_id UUID NOT NULL referencing auth.users ON DELETE CASCADE; UNIQUE(teacher_id,id); parent_id nullable UUID composite FK (teacher_id,parent_id) to same table, NO ACTION DEFERRABLE for account erasure, never cascading a collection into material; name text, name_key text, description text NOT NULL default empty, sort_order integer NOT NULL, archived_at timestamptz nullable, archived_batch_id UUID nullable, revision bigint >=1, created_at/updated_at timestamptz. Self-parent check; archive timestamp/batch both null or both present. Owner/parent/order/id index; owner/archive index. Active sibling uniqueness via partial UNIQUE NULLS NOT DISTINCT (teacher_id,parent_id,name_key) WHERE archived_at IS NULL (Postgres 17). Archived duplicates permitted, restore conflict explicit. Position not unique, dense order normalized in transaction; tie breaker UUID. Name key deterministic NFC, trim/collapse Unicode whitespace, locale-independent Unicode casefold using a pinned algorithm; verify SQL/server equivalence, DB computes/verifies key in guarded RPC, no accent stripping/transliteration. Name display NFC, internal spaces preserved. Disallow controls/bidi overrides, allow Hebrew/Russian, paths are arrays not slash strings. Validate reserved virtual views by separate discriminator, not name.
- material_library_memberships: teacher_id, collection_id, material_id, created_at; PK(teacher_id,collection_id,material_id), reverse index (teacher_id,material_id,collection_id); same-owner composite FKs to collection and learning_materials, NO ACTION DEFERRABLE, explicit account teardown order. No independent material ordering initially; use title/id or existing catalog sort. No material-side cascade or membership duplication.
- material_library_state: teacher_id PK -> auth.users ON DELETE CASCADE, revision bigint >=0, updated_at; lazily create on first write, blank read revision 0. Owner row lock serializes **all** organization mutations; no mandatory template rows. State revision advances exactly once for any effective transaction, collection row revision for each changed row including reorder. No-op keeps revision.
- material_library_receipts: teacher_id, request_id UUID, operation enum/check, canonical request_hash, response JSONB (bounded, no secrets), created_at; PK(teacher_id,request_id). Append-only, full retention for replay until account erasure, no user mutation. Dedicated domain receipts instead of transport-only agent_tool_receipts; same request from web or MCP. Evaluate storage and privacy impact; no arbitrary JSON operation input.

All four tables RLS enabled, authenticated SELECT only on collections/membership/state by auth.uid(), no direct DML or receipt access; receipt returned through guarded routines. Revoke PUBLIC/anon execution and default broad grants; explicit authenticated grants for exact routines only, service role no ordinary teacher mutation bypass (separately reviewed operator erasure/restore). SECURITY DEFINER fixed search_path, qualified relations, auth.uid() nonnull and owned teacher validation, no teacher ID input or dynamic SQL. Confirm actual inherited/default privileges and RLS in isolated tests. Public schema no secret fields.

## Tree and transaction rules

Proposed technical caps (not entitlements): 12 levels including root node, 2,000 collections including archived, 250 siblings including archived, 100,000 memberships/owner, 100 placements/material, 80 Unicode scalar name, 500 description, 100 edits or membership pairs/transaction, template <=100 nodes, import <=2,000 nodes/100,000 links via separately reviewed bounded upload path (initial interactive import chunks <=100 atomic changes; no partial hidden success), read page default 30 max 100, search 160 chars, max 20 suggestions, max 2 MiB export/import page payload and 5s DB statement/lock budget. Subtree archive/restore may touch up to 2,000 collections; no per-membership writes. Bounds include archived records; surface LIMIT_EXCEEDED, never delete to make space. Measure query plans and tune before approval; no quota/product commitment.

At transaction start acquire owner state row (INSERT ON CONFLICT then SELECT FOR UPDATE); lock referenced active material rows by UUID using FOR SHARE before placement, recheck archival and ownership. No other code path may lock material then acquire library state; existing content archive only locks material, never updates library. Archive content preserves membership; active catalog excludes archived materials by default, explicit archive filter includes them; restoring content reveals retained effective placements. Use same snapshot for list/count/uncategorized/export; library revision tracks organization only, catalog changes can invalidate material pages separately (see contracts). Tree writes check expected library revision after replay lookup. Walk proposed parent ancestry under lock, reject cycle, self-parent, archived destination and any descendant depth overflow. Direct DML denied. Collection archive marks only currently active descendants with same batch UUID; pre-archived descendants untouched. Restore only the chosen batch subtree (cannot restore a child while parent archived), preview exact collisions, require explicit separate rename/move plan before commit; no automatic reparenting or revival of older archived branches. Membership remains intact and hidden by inactive collection. Uncategorized = active material with zero active collection memberships; direct selection versus descendants explicit and distinct material IDs. Active ancestor invariant enforced. Reorder by insert before sibling UUID or null=end; full deterministic resequence includes active siblings; archived rows retain order hint, restore appends in deterministic prior order. Names across different parents can repeat; sibling conflicts fail even under concurrency.

Receipts: authorize current caller before replay; compare canonical typed payload hash including expected revision, operation and reviewed plan; exact repeat returns immutable original result with replayed=true even if current revision changed; changed payload same key rejected. Atomic writes and receipt, no partial success or fallback. Preview binds owner/operation/normalized payload/affected IDs+revisions/expiry, signed server-side, re-evaluate under lock, stale or expired rejected; browser/MCP require explicit teacher confirmation for consequential operations. Use 10-minute TTL proposed; never accept confirmation token alone as authorization. Unknown network result retry identical request before new write. Read-back independently through get/list, not receipt echo.
