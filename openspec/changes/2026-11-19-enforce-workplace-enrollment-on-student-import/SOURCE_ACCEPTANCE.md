**Verified source criteria only.** [PR #132](https://github.com/itshak/ChessCoachPal/pull/132) merged at [`28cbac4`](https://github.com/itshak/ChessCoachPal/commit/28cbac476c385c08ba93b12761e1b5bfc383a2c9). Its tested head `1977f4a2a3d45528902d0810656a34fd422c8428` and merged main share tree `d77befe0232ac4c531f822db2e16a04a2e4d8d12`. All five hosted workflows passed: [security](https://github.com/itshak/ChessCoachPal/actions/runs/45122786746), [CI](https://github.com/itshak/ChessCoachPal/actions/runs/45122786785), [synthetic restore](https://github.com/itshak/ChessCoachPal/actions/runs/45122786750), [fresh Compose](https://github.com/itshak/ChessCoachPal/actions/runs/45122786738), and [signed E2E](https://github.com/itshak/ChessCoachPal/actions/runs/45122786793). This is not production verification or authorization.

| Source scenario | Observed verification |
| --- | --- |
| Read-only review, dated write and explicit destination | Application and MCP share the canonical reviewed contract. Approved rows show identity and effects, day and timezone, and every venue; the active context is a suggestion until explicitly chosen. Ambiguity, conflicting/duplicate choices and review changes are rejected. Controlled browser fixtures cover 52 rows, keyboard/focus, and stale retirement with no redirect or write. |
| Atomic enrollment, replay and ownership | The #131 activated schema uses exact reviewed IDs, authenticated owner scope, pinned enrollment day and venue revisions, sorted locks, and all-or-nothing active enrollment. Signed fixtures cover exact replay after retirement, both archive/import lock orders, future-period rollback, same-name distinct owned students, lost acknowledgement and exact retry, foreign inputs, and one student assigned to two venues. Legacy review-less requests are exact receipt replay only. Explicitly creating an archived profile creates no current enrollment. |
| Independent historical evidence | Synthetic input contains twenty dated observations, ten dates per learner, from a reviewed register. Historical attendance identifies the workplace separately from current enrollment, creates no fabricated sessions or credits, and does not infer current enrollment for the archived learner. No real spreadsheet was accessed. |
| Authorized current and historical reads | Scoped Students roster filters, named workplace enrollment listing and student-to-workplace reverse lookup work through supported website and MCP paths. Named roster uses venue-local current-day boundaries and omits archived students; foreign and organization-wide named requests are denied. Reverse lookup reports historical-without-current independently; only approved name/ID, date and status fields are returned. |

The [ADR-0023 successor](../../../docs/adr/0023-workplace-spreadsheet-import-source-review.md) was separately approved in [#130](https://github.com/itshak/ChessCoachPal/pull/130) and is active on [merged #131](https://github.com/itshak/ChessCoachPal/commit/c1a575e489887a142d90782e7bd058990013de1f). It records the independent matching PostgreSQL bootstraps and checksum-sealed cold synthetic SQL/Storage restoration. The #132 code-only follow-up did not change the baseline, manifest or lock. Current and prior-base freeze guards and strict MCP parity passed. An older roster fixture was corrected to verify the named enrolled student and authoritative period rather than require the old one-field response; the corrected lifecycle and venue-day roster cases also passed together on a disposable stack.

## Open, separate from source

- Do not inspect the original private spreadsheet, original agent tool calls, populated beta receipt or learner data without explicit authorized scope. Their columns, original behavior and any affected records remain unverified.
- Actual deployed-image/receipt/enrollment/evidence inventory, privacy-safe reconciliation and any remediation remain one separately approved ADR-0017 operator handoff. Require target-specific authorization, independent off-host restore, teacher review and verification before mutations. An isolated local restore is not that gate.
- Contacts CRM remains a named coordination dependency: this import retains existing supported fields but creates no new contact/payer authority or dependency. Removing inherited guardian/family behavior and proving legacy mapping have not been accepted here.
- Keep this proposal active while the checklist still contains unresolved coordinated and operational acceptance. Hosted source evidence does not establish live acceptance. The [#132 main release workflow](https://github.com/itshak/ChessCoachPal/actions/runs/45125382181) skipped publishing and its [Coolify private-beta job](https://github.com/itshak/ChessCoachPal/actions/runs/45125382181/job/137528467959) was skipped. The published version remains v0.1.9.
