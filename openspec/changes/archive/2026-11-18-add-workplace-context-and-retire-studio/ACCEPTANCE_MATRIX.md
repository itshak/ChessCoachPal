## Settings and ownership

| Data or effect | Authoritative contract |
|---|---|
| UI language, notifications and credentials | Teacher preference/settings and scoped credential service. Workplace output locale does not reassign UI language or broaden account/guest access. |
| Workplace timezone, currency and output locale | First-class `workplaces` columns. When interpreting an already recorded session, stored historical snapshot/attribution takes precedence; for new or unsnapshotted records use applicable workplace fields, then the explicit teacher fallback where the operation defines one. Never rewrite old attribution to match a new selection. |
| Cancellation/makeup eligibility | For newly recorded decisions the shared make-up reader and booking RPC use captured terms. The guest notice shows the current typed local override or inherited teacher value, falling back to 24 hours where settings are unavailable. It no longer treats loose workplace JSON as a policy authority. `parity-portal-cancellation-policy.spec.ts` verifies the owned/foreign rule selection, recipient locales, default fallback and invalid bearer denial. This updates display only, without exposing credentials or granting guest authority. See the reviewed refinement below for the new typed override and historical make-up terms. |
| Compensation, rates and payable finance | `compensation_agreements` and `lib/server/compensation-agreements-service.ts` already model typed, approved, effective-dated workplace-wide terms (null student/group), or narrower scope, with independent billing account, currency, revision and confirmation. This needs no new schema for existing use. Actual payable/posted finance remains on its canonical approved ledger and separate scope; a group, active selection or generic JSON key grants no authority. |
| `workplaces.policy` JSON | Existing web/MCP contracts can carry metadata, but that does not make it a commercial authority or durable historical cancellation snapshot. Preserve only validated use-specific fields and avoid implicit overrides. The reviewed preproduction revision uses typed owned columns and captured evidence, not arbitrary metadata as an authorization rule. |

Prioritize missing scope/confirmation proofs first, then the Free Personal smoke and settings presentation/source-of-truth test. Do not close the proposal from this matrix alone.


## Reviewed preproduction policy refinement

The approved preproduction refinement implements an optional, typed cancellation window on each owned workplace. A null override inherits the typed teacher window, falling back to 24 hours where the teacher settings row has no value. An explicit zero is valid. The guest notice and shared website/MCP policy configuration are scoped to the owned workplace.

A newly recorded student cancellation snapshots the applicable notice window, source lesson start, and timely/late make-up flags at the time of the decision. Later changes to settings do not change that evidence; a same-status correction preserves the applicable terms. The booking RPC and dashboard/API eligibility checks consume the same recorded terms. Old records without historical terms remain on the existing account-wide path; we do not invent or backfill a workplace rule.

Portable imports are teacher-authored, not attestation. They can retain a claimed snapshot as unverified; it cannot authorize automatic make-up or new invoice/credit eligibility. Existing observed evidence may be replayed exactly but not replaced. Physical restore preserves the observed provenance. This refinement concerns make-up eligibility; it does not change existing finance classifications, rates, or posted amounts. The change requires a reviewed exact successor lock and new hosted checks, not an unguarded baseline change.
