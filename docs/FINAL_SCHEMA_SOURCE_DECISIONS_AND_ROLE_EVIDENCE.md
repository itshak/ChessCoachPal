## Relation × role review

Expected direct application surface below is a **source-derived intent**, not an assertion that deployed roles behave accordingly. `O` is authenticated owning teacher; `F` is a separately authenticated foreign teacher; `A` is anonymous; `S` is a headless service role. Guests and delegated OAuth clients go through their existing application routes, not a signed teacher or an anon table grant. RLS is not a substitute for effective ACL, column privileges, or mutation invariants when S bypasses RLS. A blank behavior must be tested, explicitly proven unreachable, or carried as a blocker.

## How to close complete coverage without confusing static and behavioral checks

1. **Build the closure on the final SHA.** On separate scratch databases bootstrap exact `main` and selected candidate and capture metadata read-only where both support it; where old baseline cannot bootstrap in an equivalent engine, enumerate its SQL definitions and record that limitation. Diff normalized relation ownership, columns, constraints/FKs, policy commands and qualifiers, grants, triggers and their target routines. Inventory public routine signatures by identity arguments, privilege, owner, SECURITY DEFINER and search path, then review changed bodies for additional relation reads/writes and calls; include added, modified, formerly exposed and removed signatures. Map every changed object to a check or explicit reason it is unreachable. Comparing candidate to itself checks convergence, not this scope. Do not close SCH-07 from a name scan or infer every trigger/policy is unchanged from an unchanged table declaration.
2. **Check effective ACL boundaries, then distinct signed behavior.** In disposable catalog assertions use `has_table_privilege`, column grants and `has_function_privilege` to catch PUBLIC/inherited access; confirm schema USAGE and RLS for all touched tables. For true trigger-only helpers require no PUBLIC/A/O/F/S direct execution and exercise the allowed parent operation. For each exposed changed definer record O/F/A/S with positive allowed calls and actual prohibited calls, correct identity, fixed search path, owned targets, stale revision/replay and no state/receipt changes after rejection as applicable. For tables seed two independently authenticated tenants and an actual row in each applicable domain, prove O selective reads/writes and F/A denials, and test S guard cases. Zero rows and SQL permission-denied are distinct outcomes. Portal guest tests must use an actual scoped token; delegated MCP checks must use scoped OAuth plus server-side entitlement. No privilege grant is modified by this plan.
3. **Reuse exact assertions, expand only missing cells.** Present fixture covers 11 effective signatures: five owner-only (`ccp_canonical_slot_cancel_unmaterialized`, `ccp_canonical_slot_revoke_unmaterialized_cancellation`, `ccp_canonical_terminal_slot_split`, `ccp_canonical_slot_edit_scoped`, `ccp_canonical_reschedule_unmaterialized_slot`), worker-only `ccp_rating_refresh_claim/finalize`, and four internal helpers. Entitlement entry points (`ccp_entitlement_summary`, `ccp_effective_capability`, `ccp_reconcile_entitlement_counts`), changed historical import/capture, material, finance and roster functions and all other changed identities must be reconciled by the closure in step 1; no assumption that unused service EXECUTE is intentional. Where a shared setup covers multiple cells, keep independent signed readback or rollback evidence and exact named test; document untested cells rather than rounding up counts.
4. **Record release evidence.** Finish named Phase 2 scenarios (including quota deduplication, scoped evidence and supported client parity), tie all eight decisions to exact code/evidence, then record source inventory, materialized Row audit, independent structural comparison, exact-head CI/E2E/security/Compose/synthetic restore, named skips and no-independent-DDL handoff. Only after this source gate should the freeze lock be accepted. Phase 0 compares the exact source and a fresh disposable target; it does not substitute for the live target inventory. Under ADR-0017 private deployed inventory, encrypted independent restore, data mapping, operator authorization, cutover and real-provider rollout remain a separate gated process; this register grants no access or authority for those steps.

## Materialized access delta and focused verification

Read-only Format 3 catalogs on merged main and the independently bootstrapped `2b6d4e59` candidate found 18 new and nine structurally modified relations, 41 added, eight modified and three retired routine identities, and no public schema or default ACL changes. At that checkpoint five changed identities were authenticated-only, seven authenticated plus service, 32 service-only, and eight had no app execute or were retired. None was executable by anon. A conservative SQL control-flow pass reached 71 relation names including existing restore allowlists and trigger targets. These are not 71 new grants. Read the [structural export evidence](SCHEMA_FREEZE_STRUCTURAL_COMPARISON.md), and do not treat effective-role catalog data as row-level behavioral proof.

The focused follow-up tests in the [acceptance matrix](FINAL_SCHEMA_ACCEPTANCE_MATRIX_2026-11-21.md) verify the six public product/rating catalogs, eight per-account commercial tables, seven dual-role routine entry points and selected historical lesson, evidence and rating boundaries. Billing offer identifiers and material evidence delete privileges were tightened by that follow-up. A private beta was not inspected.
