# ChessCoachPal custom MCP connectors — current contract

> **Deployment terminology (ADR-0018):** ChessCoachPal is operator-only SaaS; any "self-hosting" references here describe our infrastructure/CI, never customer-hosted product support. [Current policy](adr/0018-operator-only-saas-and-tenant-scaling.md).

**Updated 2026-11-15.** Current exact tool identifiers use `ccp_<domain>_<action>` and the public HTTPS endpoint is `https://chesscoachpal.com/mcp`. The pre-v1.0.0 contract intentionally has **no** `ccp_v1_*` aliases ([ADR-0006](adr/0006-unversioned-mcp-tool-names.md)). Source of truth for tool discovery is the published `tools/list` generated by `lib/server/agent-tools.ts`, **not an old static list**.

**Real-client status:** A real Claude Desktop conversation successfully exercised synthetic student/session/material CRUD, including material create/get, independent student/session links, evidence record/void and report read-back, after PR [#79](https://github.com/itshak/ChessCoachPal/pull/79) fixed the canonical material input-schema discoverability problem. Claude's connector settings showed **88 read-only + 95 write** tools at that time. That does **not** establish that every tool or future conversation can be loaded; **real ChatGPT** end-to-end acceptance remains unverified. See [LOCAL_CLIENT_ACCEPTANCE.md](LOCAL_CLIENT_ACCEPTANCE.md).

## Server and owner authorization

- Use HTTPS on an accessible trusted origin; **never give the AI client the Supabase service-role key**, database password, `MCP_SESSION_ENCRYPTION_KEY`, Lichess token, email API key, payment/AI provider secret, OAuth code or user password.
- Configure server-only `MCP_PUBLIC_ORIGIN=https://your-domain.example` (the exact externally reachable origin) and `MCP_SESSION_ENCRYPTION_KEY` according to `.env.example` and the self-hosting guide. Protect and back up server-only encryption keys.
- Expose `/mcp`, `/.well-known/oauth-protected-resource`, `/.well-known/oauth-authorization-server`, `/oauth/register`, `/oauth/authorize`, `/oauth/token`, and `/oauth/revoke`. Do not cache tokens/authorization responses at proxies; rate-limit public registration and login/approval.
- Teachers sign in through the normal browser and approve the **specific** delegated scopes. A read-only `coach:read` connector should not see write tools; `coach:write` is required for approved mutations. OAuth access/refresh token expiry and revocation must be tested against the actual client.

## Claude Desktop

1. In a supported Claude client, add a remote custom connector using the exact HTTPS `/mcp` URL. Follow the current official [Claude remote MCP setup guide](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) for current controls and plan eligibility.
2. Authorize the **synthetic** teacher, review the permissions and enable ChessCoachPal in the conversation. Use a **new conversation** when retesting tools after a schema or deployment change.
3. Request an exact-name ToolSearch for `ccp_learning_materials_create` and `ccp_learning_materials_get`. **Seeing a tool enabled in connector settings is insufficient:** the conversation's deferred ToolSearch might load only a subset. Verify discovery of the tool **schema**, then call it and independently read back its returned ID.
4. To test the full material path, create an owned drill, link it independently to a student and session, record separately confirmed `assigned`/`taught` evidence, void `assigned` with its revision/reason, then read history with and without voids and default progress/aggregate counts.
5. Never infer mastery, duplicate students from two aliases, or success from the tool's receipt alone.

## ChatGPT

Add or connect a custom MCP server/app using the same HTTPS `/mcp` URL and delegated OAuth flow **where your current ChatGPT workspace supports write-capable custom MCP connections**. Consult [OpenAI's current custom MCP instructions](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt); the exact UI and permissions differ by plan and can change. Do not assert write capability based solely on connector registration. The real ChatGPT create/edit/report/read-back and OAuth revocation tests remain **pending** and must be recorded independently of the Claude result.

## Tool expectations and retries

The live server exposes a broad named catalogue (the 2026-11-15 Claude settings listed 183 read/write tools). **Do not freeze that count or use it as a behavioral test.** Examples verified through synthetic CI/Claude exercise include:

| Goal | Relevant named tools |
| --- | --- |
| Student identity and roster | `ccp_students_roster`, `ccp_students_resolve`, `ccp_students_profile_edit`, `ccp_workplaces_enrollments` (named current periods), `ccp_students_workplaces` (reverse current versus historical) |
| Scheduling and attendance | `ccp_private_sessions_create`, `ccp_sessions_details`, `ccp_sessions_complete`, `ccp_session_notes_save` |
| Dated coaching/skill evidence | `ccp_student_skill_assessments_record`, `ccp_students_chess_history`, `ccp_student_ratings_record` |
| Materials and audit | `ccp_learning_materials_create`, `ccp_learning_materials_get`, `ccp_material_links_create`, `ccp_material_links_list`, `ccp_materials_history_record`, `ccp_materials_history_void` |
| Reports | `ccp_reports_student_progress`, `ccp_lessons_history_unified`, `ccp_materials_aggregate` |

**Important subtlety:** every optional advertised schema field must reach runtime MCP dispatch. PR #81 fixed a bug where `assessedOn` was accepted but not forwarded. Use explicit non-default inputs and read the physical persisted date back; absent `assessedOn` means **today in the teacher's local timezone** and present `assessedOn` must be honored. An idempotency key is immutable: retries use the same UUID+payload; changed payload must fail. Revision-checked updates require the latest `updated_at`/revision and teacher confirmation.

A full student name and alias may refer to the same UUID. The resolver should report one identity, while a proposed lesson roster containing *both* strings blocks committing duplicate attendance.

## Troubleshooting by layer

| Symptom | First check |
| --- | --- |
| Connector appears registered but deferred ToolSearch returns no matching tool | Is exact tool name in live `tools/list`? Does its **root JSON Schema** load via exact-name search in a **new** client conversation? Was the current deployed SHA updated? |
| Tool is listed but invocation changes nothing | Trace `tools/call` → `agent-tools.ts` dispatch → shared service → SQL/RLS; check optional field forwarding, revision and idempotency; read back independently |
| `DATABASE_ERROR` after a field was added to source | Inspect the **physical** hosted project schema/columns, RLS/grants, migrations ledger and auth identity; the source SQL file existing in Git does not apply itself to an older database |
| Unauthorized/forbidden/read-only | Check delegated token scopes, expiry/revocation and teacher ownership; never relax RLS to “make the tool work” |
| A name and alias resolve to the same student | Not a duplicate DB row; one name per roster member; disambiguate different students by stable ID |
| Progress rating is null despite snapshots | Check actual snapshots, time control, source, observation timestamp, and report aggregation; grade/strength/profile ratings are distinct |
| Previously created evidence disappears from default aggregates | Check whether it was **voided**; use audit `includeVoided:true` for preserved history |

For robust investigation and Supabase reset/security hazards, read the [reusable engineering playbook](MCP_SUPABASE_RELIABILITY_PLAYBOOK.md), [OpenSpec parity](../openspec/specs/teacher-mcp-parity/spec.md) and [ADR-0007](adr/0007-mcp-supabase-contract-and-release-evidence.md). Do not expose private student data or tokens in GitHub evidence.


## Draft native finance operations (not yet release-accepted, 2026-11-19)

The immutable financial ledger candidate has individually named MCP operations ccp_finance_ledger_list, ccp_finance_obligation_approve, ccp_finance_payment_record, ccp_finance_allocation_record and ccp_finance_reversal_record; matching website endpoints are under /api/finance-ledger. Read-only scopes expose only the list operation. The new write operations require teacher-owned scope and an explicitly confirmed exact request; they cannot initiate provider charges or refunds. Teacher-confirmed manual receipts are distinct from provider-verified funds. See docs/NATIVE_FINANCE_LEDGER.md and the active compensation OpenSpec. The old guardian-based invoice tools remain unaccepted and must be retired/rebuilt before v1 cutover.
